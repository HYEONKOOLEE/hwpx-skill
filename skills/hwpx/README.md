# hwpx — 한글 문서(.hwp / .hwpx) 읽기·편집·저장 스킬

한글 문서를 Claude가 직접 **읽고, 고치고, 만들고, 저장**할 수 있게 해주는 스킬입니다.
`.hwpx`는 물론 **`.hwp`를 그대로 올려도** 자동 변환해 처리하고, **올린 형식 그대로 되돌려줍니다**
(한컴오피스 설치 불필요).

> **버전** v1.4.1 · **최종 수정** 2026-09-05
> **이 폴더 하나로 완결됩니다. 함께 설치해야 하는 다른 스킬은 없습니다.**

---

## 무엇을 할 수 있나

| 하고 싶은 것 | 예시 요청 |
|---|---|
| 새 한글 문서 만들기 | "이 내용으로 보고서 한글 파일 만들어줘" |
| 공문·기안문 작성 | "이 안건으로 공문 하나 써줘" |
| 양식에 내용 채우기 | "이 hwpx 양식에 우리 회사 정보로 채워줘" |
| **기존 원고 수정** | "이 한글 원고에서 3장 내용만 고쳐줘" |
| `.hwp` 파일 그대로 처리 | "이 hwp 파일 열어서 2쪽 표만 바꿔줘" |
| **양식 없이 규정·매뉴얼 작성** | "출장비 지급 규정 만들어줘" · "안전관리 지침서 써줘" |

특히 **기존에 완성된 원고를 고치는 작업**을 별도 절차(`references/edit-existing.md`)로
분리해 둔 것이 이 스킬의 핵심입니다. 이 절차를 거치지 않고 새로 만들듯 처리하면
원본 서식이 깨지고 내용이 유실됩니다.

### 범위 밖

누름틀(필드) 서식 자동 채우기·메일머지, 한글 앱 매크로 자동화, PDF 변환은 이 스킬이 다루지 않습니다.
대신 그런 서식이라도 **텍스트를 직접 치환하는 방식으로는 편집할 수 있습니다.**

## 설치

### 방법 1 — `.skill` 파일 (가장 간단)

전달받은 `.skill` 파일을 Claude 대화창에 올린 뒤, 나타나는 **저장** 버튼을 누르면 끝입니다.

### 방법 2 — 폴더 직접 복사

`.skill` 파일은 확장자만 다른 zip입니다. 확장자를 `.zip`으로 바꿔 압축을 풀고,
나온 `hwpx` 폴더를 통째로 스킬 폴더에 넣으세요.

```
~/.claude/skills/hwpx/          (개인 스킬)
/mnt/skills/user/hwpx/          (환경에 따라 다름)
```

### 의존 패키지

문서를 실제로 만들 때 아래 패키지가 필요합니다. Claude가 알아서 설치하지만,
막히면 직접 실행하세요.

```bash
pip install python-hwpx --break-system-packages   # 필수
npm i @rhwp/core                                 # .hwp 파일을 직접 올릴 때만
```

> ### ⚠️ `@rhwp/core`는 npm 패키지입니다 — 설치할 "다른 스킬"이 아닙니다
>
> 이름 때문에 "rhwp 스킬도 같이 깔아야 하나?" 하는 오해가 자주 생깁니다. 정리하면:
>
> | 이름 | 정체 | 필요 여부 |
> |---|---|---|
> | **`@rhwp/core`** | npm 라이브러리(Rust+WASM HWP 파서) | `.hwp`를 직접 올릴 때만. `npm i` 한 줄 |
> | `rhwp` CLI · 누름틀 채우기 스킬 | 메일머지용 **별개 도구** | **불필요.** 이 스킬과 무관합니다 |
>
> `npm i @rhwp/core`를 건너뛰어도 `.hwpx` 작업은 전부 정상 동작합니다.

## 사용법

설치 후에는 **평소처럼 한국어로 요청**하면 됩니다. 아래 표현이 나오면 스킬이 자동으로 켜집니다.

> "한글 문서로 만들어줘" · "hwpx로 저장해줘" · "한글파일" · "공문 써줘" · "기안문"
> "이 한글 원고 수정해줘" · "이 양식에 채워줘"

Word(.docx)가 필요하면 이 스킬이 아니라 `docx` 스킬이 쓰입니다.

## 폴더 구성

```
hwpx/
├── SKILL.md                      ← 스킬 본체 (Claude가 읽는 지침)
├── README.md                     ← 이 파일
├── CHANGELOG.md                  ← 변경 이력
├── references/
│   ├── edit-existing.md          ← 기존 원고 편집 절차 (가장 중요)
│   ├── report-style.md           ← 보고서 서식 규격
│   ├── official-doc-style.md     ← 공문서 서식 규격
│   └── xml-internals.md          ← HWPX 내부 구조 (문제 해결용)
├── scripts/
│   ├── clear_layout_cache.py     ← 텍스트 수정 후 필수 후처리
│   ├── verify_hwpx.py            ← 전달 전 검증 (검사 8종)
│   ├── hwp_bridge.mjs            ← .hwp ↔ .hwpx 양방향 변환
│   ├── autofit_table_rows.py     ← 표 행 높이 자동 조정
│   └── fix_namespaces.py         ← 네임스페이스 손상 복구
├── assets/
│   ├── report-template.hwpx      ← 공공기관 표준 보고서 양식
│   └── form2.hwp                 ← 공공기관 기본 계획 보고 양식
└── evals/evals.json              ← 동작 검증용 테스트 케이스
```

## 꼭 알아둘 4가지

1. **텍스트를 한 글자라도 바꿨으면 레이아웃 캐시를 지워야 합니다.**
   안 지우면 한글에서 열었을 때 글자가 겹치거나 잘려 보입니다.
   → `scripts/clear_layout_cache.py`

2. **다시 압축할 때는 `mimetype`을 무압축으로 맨 앞에 넣어야 합니다.**
   순서나 압축 방식이 틀리면 한글이 파일을 아예 열지 못합니다.

3. **표의 행이나 열을 지웠다면 병합 정합성을 함께 맞춰야 합니다.**
   세로로 병합된 셀이 없어진 행을 계속 가리키면 한글이 파일을 **아예 열지 못합니다.**
   관공서 서식은 겉보기와 달리 전체가 표 하나인 경우가 많아 특히 주의가 필요합니다.

4. **전달 전 반드시 검증하세요.**
   → `scripts/verify_hwpx.py` (검사 5번이 위 3번을 자동으로 잡아냅니다)

네 가지 모두 `SKILL.md`에 절차가 적혀 있고, Claude가 자동으로 따릅니다.

## 동봉 양식 관련 안내

`assets/`의 두 양식은 **공공기관 보고서 서식을 익히기 위한 일반 샘플**입니다.
특정 기관의 실제 문서가 아니며, 자리표시자(`기관명`, `제 목`, `2000. 00. 00`,
`내용을 입력하세요` 등)로 채워져 있습니다.

- `form2.hwp`의 차례 항목에 `유네스코 한국위원회 사업지원`이라는 **예시 문구**가
  남아 있습니다. 실제 사용 시 본인 내용으로 치환하면 됩니다.
- 소속 기관에 별도 지정 양식이 있다면, 그 파일을 `assets/`에 넣고
  `SKILL.md`의 템플릿 경로만 바꿔 쓰는 것을 권합니다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 한글에서 파일이 안 열림 | ① 표의 행·열을 지웠다면 `rowSpan`·`rowCnt`를 맞췄는지 ② 재압축 시 `mimetype`이 맨 앞·무압축인지 |
| 글자가 겹치거나 잘림 | 레이아웃 캐시를 지웠는지 |
| 표가 삐뚤어짐 | `autofit_table_rows.py`를 돌렸는지 |
| 본문이 전부 가운데 정렬 | `set_paragraph_format` 인자를 생략했는지 (SKILL.md R5) |
| 쪽수가 비정상적으로 많음 | `page_break_before`가 전파됐는지 (SKILL.md R5) |
| 태그 오류·파싱 실패 | `fix_namespaces.py`로 복구 시도 |
